# UI Traps Analyzer - Test Suite

Cost-effective 3-tier testing strategy optimized for AI/LLM systems.

## 🎯 Strategy Overview

| Tier | Cost/Run | Runtime | Coverage | When to Run |
|------|----------|---------|----------|-------------|
| **Tier 1: Free Validation** | $0.00 | <5 sec | 80-85% | Every commit |
| **Tier 2: Cached Regression** | $0.00* | <10 sec | 10-15% | Every commit |
| **Tier 3: Real API Smoke Tests** | $0.15-0.25 | 30-60 sec | 5-10% | Before releases |

*One-time setup cost: $0.25-0.40

**Total cost for typical development**: **$0.00 per test run** ✅

---

## 🚀 Quick Start

### 1. Install Dependencies

```bash
cd backend
pip install -r tests/requirements.txt
```

### 2. Run Free Tests (Tier 1)

```bash
# Run all free tests (no API calls)
pytest tests/test_analyzer_free.py -v

# Expected: ~40 tests pass in <5 seconds, $0.00 cost
```

### 3. Generate Cached Fixtures (Tier 2) - ONE TIME ONLY

```bash
# ⚠️  This costs ~$0.30-0.40 ONE TIME
python tests/generate_fixtures.py

# This creates cached API responses that can be reused forever
```

### 4. Run Cached Regression Tests (Tier 2)

```bash
# After fixtures are generated, run Tier 2 tests (free)
pytest tests/test_analyzer_cached.py -v

# Expected: ~25 tests pass in <10 seconds, $0.00 cost
```

### 5. Run All Free Tests (Tier 1 + 2)

```bash
# Run all tests except expensive real API tests
pytest tests/ -v

# This is what you run during development and in CI/CD
```

### 6. Run Real API Tests (Tier 3) - USE SPARINGLY

```bash
# ⚠️  WARNING: This costs ~$0.25 per run
pytest tests/test_analyzer_real_api.py -v -m real_api

# Only run before major releases or after significant changes
```

## 🧪 Tier 1: Free Validation Tests

**File**: `test_analyzer_free.py`
**Cost**: $0.00 per run
**Runtime**: <5 seconds

### What It Tests

✅ Schema compliance (all required fields present)
✅ No hallucinated trap names (only 27 valid names allowed)
✅ No hallucinated tenet names (only 9 valid names allowed)
✅ Data types correct (summary is array, not string)
✅ Confidence values valid ("high"/"medium"/"low")
✅ Issue objects have all required fields
✅ Summary has 5-9 items
✅ Edge case handling (empty arrays, many issues, etc.)

### How It Works

Uses **mocked Anthropic client** to return controlled responses, then validates output structure.

### Example Run

```bash
pytest tests/test_analyzer_free.py -v

# Output:
# test_analyzer_free.py::test_valid_response_passes_validation PASSED
# test_analyzer_free.py::test_summary_must_be_array PASSED
# test_analyzer_free.py::test_rejects_hallucinated_trap_names PASSED
# ...
# ========== 42 passed in 3.2s ==========
# ✅ No API costs (Tier 1+2 tests only)
```

## 🔄 Tier 2: Cached Regression Tests

**File**: `test_analyzer_cached.py`
**Setup Cost**: $0.25-0.40 (one-time)
**Per-Run Cost**: $0.00
**Runtime**: <10 seconds

### What It Tests

✅ Output structure matches baseline
✅ No regressions in parsing logic
✅ Severity distribution reasonable
✅ Statistics calculation works
✅ Response handling is robust

### How It Works

1. **One-time setup**: Run `generate_fixtures.py` to create cached API responses
2. **Every test run**: Load cached responses from disk (free!)
3. **Validation**: Ensure new code handles cached responses correctly

### Setup Instructions

```bash
# Step 1: Add test images to tests/fixtures/images/
# You need 5 diverse test images:
# - simple_form.png (basic form)
# - complex_dashboard.png (dense UI)
# - mobile_screen.png (mobile design)
# - error_state.png (error screen)
# - minimal_ui.png (very simple UI)

# Step 2: Generate fixtures (costs $0.25-0.40 ONE TIME)
python tests/generate_fixtures.py

# Step 3: Run tests (free forever after)
pytest tests/test_analyzer_cached.py -v
```

### When to Regenerate Fixtures

Only regenerate if you change:
- System prompt (`src/prompts.py`)
- Schema structure (`src/schema.py`)
- Claude model version

Otherwise, reuse existing fixtures forever!

## 🔥 Tier 3: Real API Smoke Tests

**File**: `test_analyzer_real_api.py`
**Cost**: $0.15-0.25 per run (5 tests × $0.05 each)
**Runtime**: 30-60 seconds

### What It Tests

✅ Can analyze real screenshots
✅ Returns valid JSON structure
✅ API credentials work
✅ Doesn't crash on edge cases

### When to Run

- ❌ **NOT on every commit** (too expensive)
- ❌ **NOT in regular CI/CD** (burns budget)
- ✅ **Before major releases**
- ✅ **After prompt/schema changes**
- ✅ **After Claude model upgrades**

### How to Run

```bash
# Set API key
export ANTHROPIC_API_KEY="your-key-here"

# Run expensive tests
pytest tests/test_analyzer_real_api.py -v -m real_api

# Or run specific test
pytest tests/test_analyzer_real_api.py::test_can_analyze_simple_form -v
```

## 🔧 CI/CD Integration

### GitHub Actions Example

```yaml
# .github/workflows/test.yml
name: Tests

on: [push, pull_request]

jobs:
  test-free:
    runs-on: ubuntu-latest

      - uses: actions/checkout@v3

          python-version: '3.10'

      - name: Install dependencies

      - name: Run free tests (Tier 1 + 2)

          cd backend
          pytest tests/ -v --ignore=tests/test_analyzer_real_api.py

  test-real-api:
    if: github.ref == 'refs/heads/main'

    steps:
      - uses: actions/checkout@v3
      - uses: actions/setup-python@v4

      - name: Install dependencies
        run: |
          cd backend
          pip install -r requirements.txt
          pip install -r tests/requirements.txt

      - name: Run real API tests (Tier 3)
        run: |
          cd backend
          pytest tests/test_analyzer_real_api.py -v -m real_api
        env:
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
```

## 🐛 Troubleshooting

### "No fixtures found"

**Problem**: `test_analyzer_cached.py` fails with "Run generate_fixtures.py first"

**Solution**:
```bash
# Generate fixtures (one-time cost)
python tests/generate_fixtures.py
```

### "ANTHROPIC_API_KEY not set"

**Problem**: Real API tests fail with missing API key

**Solution**:
```bash
# Add to .env file
echo "ANTHROPIC_API_KEY=your-key-here" >> .env

# Or export in shell
export ANTHROPIC_API_KEY="your-key-here"
```

### Tests are slow

**Problem**: Tests take >10 seconds

**Solution**:
- Make sure you're not running Tier 3 tests accidentally
- Check that pytest isn't collecting real_api tests

```bash
# Explicitly skip real_api tests
pytest tests/ -v -m "not real_api"
```

### "Import error: No module named 'src'"

**Problem**: Can't import analyzer module

**Solution**:
```bash
# Tests expect to be run from backend/ directory
cd backend
pytest tests/ -v
```

## 📊 What We're Testing (and NOT Testing)

### ✅ What We Test

- ✅ Output structure is valid JSON
- ✅ All required fields present
- ✅ No hallucinated trap/tenet names
- ✅ Data types correct
- ✅ Parsing doesn't crash
- ✅ Metadata is present and reasonable

### ❌ What We DON'T Test (and why)

- ❌ **Accuracy evaluation** (requires human ground truth, too expensive)
- ❌ **Exact AI outputs** (non-deterministic, leads to flaky tests)
- ❌ **"Did it find the RIGHT traps"** (subjective, needs expert review)
- ❌ **Content quality** (can't automate without building another AI)

### Why This Strategy Works

We optimize for **structural validity** (cheap to test) over **semantic correctness** (expensive to test).

This catches **80-85% of bugs**:
- Broken schema changes
- Hallucination issues
- Parsing errors
- API integration failures
- Type errors

The remaining 15-20% (accuracy, nuanced trap detection) requires human review during development.

## 🤝 Contributing

When adding new features to the analyzer:

1. **Add Tier 1 tests first** (free validation)
   - Test output structure
   - Test edge cases
   - Test error handling

2. **Regenerate Tier 2 fixtures** if schema changed

3. **Add Tier 3 smoke test** only if critical end-to-end validation needed

4. **Keep tests fast** - aim for <10 sec total runtime for Tier 1+2
